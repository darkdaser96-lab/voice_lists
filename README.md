# voice_lists

Telegram-бот голосовых и текстовых заметок по спискам. Вебхук на Vercel: голос → Groq Whisper, команды → Groq chat (один JSON), списки и заметки в **Supabase** (таблицы `lists` / `notes` / `reminders`).

## Что умеет

- **Список по умолчанию — «Стикеры»**; при показе заметки — inline-кнопки (1–4 в столбец, 5+ по две в ряд).
- **Миграция** legacy «Входящие» → «Стикеры» в БД при загрузке чата.
- **Добавить / показать / новый список** — голос или текст («в покупки молоко», «покажи покупки»).
- **Удалить заметку** — одну (номер, кусок текста) или последнюю: «удали молоко из покупок», «удали вторую заметку».
- **Очистить список** (`clear_list`) — «очисти покупки», «очисти список покупки», «очисти напоминания»: удаляются все заметки, сам список (кнопка) остаётся. Для «Напоминания» будущие (неотправленные) напоминания **не трогаются**, пока явно не попросить «отмени напоминания» / «очисти напоминания и отмени их» (`cancel_reminders: true`).
- **Удалить список** (`delete_list`) — «удали список покупки», «убери список покупки», «удали покупки целиком»: удаляются список и все его заметки, кнопка пропадает. Обычные списки удаляются сразу; системные «Стикеры» и «Напоминания» — только после подтверждения inline-кнопками «Да, удалить» / «Отмена» (или ответом «да»).
- Если списка нет — бот так и говорит: «Списка «X» нет.» и перечисляет существующие.
- **Переименовать** — «переименуй покупки в дела»; если имя занято или старого нет — отказ без затирания.
- **Избранное** — «покупки в избранное» / «убери звезду с покупок»; на кнопке и в «покажи» префикс ★.
- **Поднять список** — «подними покупки»; избранные сверху, внутри группы ручной порядок.
- **Напоминания** — «напомни завтра в 10 позвонить», «напомни 29 сентября в 18:00 оплатить счёт». Время всегда Europe/Moscow; если время неясно — бот спросит, не угадывает. Пишет в `reminders` и дублирует текст в список «Напоминания».
- **Пунктуация** — в `note` модель правит знаки, смысл и слова не выдумывает.

Клавиатура: «Новая заметка», «Удалить заметку», затем списки (★ у избранных). Отмена: `/cancel`.

## База (Supabase)

Клиент ходит только в schema **public**: `from('lists')` / `from('notes')` / `from('reminders')` → PostgREST `/rest/v1/...`. Без выдуманных путей и без DDL из кода.

### Один раз: создать таблицы в Dashboard

1. Открой проект → **SQL Editor** → New query.
2. Вставь и выполни:

```sql
create table if not exists public.lists (
  chat_id text not null,
  name text not null,
  starred boolean not null default false,
  sort_order int not null default 0,
  primary key (chat_id, name)
);

create table if not exists public.notes (
  id bigint generated by default as identity primary key,
  chat_id text not null,
  list_name text not null,
  body text not null,
  created_at timestamptz not null default now()
);

create index if not exists notes_chat_list_idx
  on public.notes (chat_id, list_name, id);

-- API: таблицы в public обычно уже в Data API; service role обходит RLS.
grant all on table public.lists to service_role;
grant all on table public.notes to service_role;
grant usage, select on all sequences in schema public to service_role;
```

3. Env на Vercel: `SUPABASE_URL` = `https://<project-ref>.supabase.co` (без `/rest/v1`), `SUPABASE_SERVICE_ROLE_KEY` = service_role.

Проверка: `GET /api/bot` → поле `db: "ok"`, если `select` из `lists` проходит. Ключи не логируются.

В RAM на инстансе остаются только шаги UI (`step`, `pendingDeletes`). Ключи **никогда** не кладутся в Git/HTML.


## Напоминания

Таблица `public.reminders` уже должна быть создана (колонки как минимум: `chat_id` text, `body` text, `fire_at` timestamptz, `sent` boolean; желательно `id`). Код **не** создаёт таблицу сам.

Планировщик (cron / внешний scheduler) периодически дергает:

`GET` или `POST` https://voice-lists-ten.vercel.app/api/remind

Эндпоинт выбирает непросланные (`sent=false`) с `fire_at <= now`, шлёт в Telegram «Напоминание: …» и ставит `sent=true`. Часовой пояс интерпретации фраз — **Europe/Moscow**.

Примеры фраз: «напомни завтра в 10 позвонить врачу», «напомни сегодня в 18 купить молоко», «напомни 29 сентября в 15:30».

### Очистка и удаление списка «Напоминания» / «Стикеры» (выбранная политика)

- «очисти напоминания» — удаляет заметки списка «Напоминания», **неотправленные напоминания остаются** и придут в срок.
- «отмени напоминания» / «очисти напоминания и отмени их» — очищает список и **удаляет все неотправленные напоминания** чата (`reminders` где `chat_id = X` и `sent = false`).
- «удали список напоминания» — после подтверждения («Да, удалить») удаляются список «Напоминания», все его заметки **и все неотправленные напоминания этого чата** (`chat_id = X`, `sent = false`). Следующее «напомни …» создаст список «Напоминания» заново (пустым, с новой заметкой).
- «удали список стикеры» — после подтверждения удаляются все заметки «Стикеров». Стикеры — список по умолчанию, вернётся пустым (строка списка пересоздаётся сразу, звезда снимается).
- Подтверждение — stateless callback_data (`dl:r`, `dl:s`, `dl:no`), работает на любом serverless-инстансе без RAM.
